# Machine setup

Per-machine setup for a Windows host, done once before setting up any environment. Complete the [Host prerequisites](README.md#host-prerequisites) first, then this doc, then [setup-environment.md](setup-environment.md).

## 1. Create the Internal switch and assign the host IP

The isolated network for guests is a Hyper-V **Internal virtual switch** (host + VMs, no internet). `configamatron run-proxy` supplies DHCP and DNS on it. The host IP you assign here is stable, and it is the one value that threads through the entire setup:

> **One host IP, used everywhere:** the static IPv4 you assign to the host's `vEthernet (<SwitchName>)` adapter is simultaneously the SMB server address, the IP that `host-allow-vm-inbound.ps1` reports, the `run-proxy --forward-listen` target, and the `<host-ip>` argument to the guest's `05-*` network scripts. This stays the same during guest setup (when network access is direct to the internet) and after the guest is isolated (when traffic must go through the proxy).

> **Two host addresses, only one stable.** The Default Switch address used during a guest's NAT phase is regenerated across host reboots. Look it up with `Get-NetIPAddress -InterfaceAlias 'vEthernet (Default Switch)' -AddressFamily IPv4` when needed.

First, identify which subnet will be used as an isolated network for your VMs. Run `ipconfig` to find a subnet that is not taken (`n` in `192.168.n.x`). The host IP will be `.1` in that subnet. For this doc set we'll assume the `192.168.67.x` subnet is used, so the host is `192.168.67.1`.

In an **Administrator** PowerShell on the host:

```powershell
New-VMSwitch -Name "configamatron-internal" -SwitchType Internal
# Assign a stable host IP on the resulting vEthernet adapter (no DHCP on an Internal switch):
New-NetIPAddress -InterfaceAlias "vEthernet (configamatron-internal)" -IPAddress 192.168.67.1 -PrefixLength 24
```

## 2. Open the host firewall for the proxy

This step is invoked from inside an environment (the script is generated by `configamatron init` — see [setup-environment.md](setup-environment.md)), but its effect is scoped to the host's Internal-switch adapter, not to any one environment. Do it once, using whichever environment you set up first; later environments don't need to repeat it unless the adapter or its IP changes.

In an **Administrator** PowerShell, run:

```powershell
powershell -File .configamatron\proxy\host-allow-vm-inbound.ps1
```

This opens inbound Envoy (`80`/`443`), DNS (`53`), and DHCP (`67`) from the VM's Internal-switch adapter, and _prints the host IP you need to use in guest-side setup_.

- It defaults to the `vEthernet (configamatron-internal)` adapter; pass `-AdapterAlias` if your Internal switch uses a different name (`Get-NetIPConfiguration` lists them).
- Safe to re-run if the host's IP on that network changes.
- It runs `run-proxy` from a dedicated private copy of `node.exe` so the firewall's program-scoped rule can't be inherited by any other use of a shared interpreter (see [ADR-0003](docs/adr/0003-transparent-interception-and-network-isolation-boundary.md)).
