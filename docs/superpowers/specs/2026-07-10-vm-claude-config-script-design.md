# VM claude-config script (`08-claude-config.sh`) + JSON-merge test coverage

Date: 2026-07-10

## Problem

Following `usage.md` to bring up an isolated VM, the copied-out Claude credential
does not work: the `claude` CLI refuses to run until `~/.claude.json` carries
`"hasCompletedOnboarding": true`. `usage.md` step 8 also copies the placeholder
credential into place by hand:

```
cp /mnt/hgfs/vm-shared/credentials.json ~/.claude/.credentials.json
```

A plain copy goes stale if the environment's `credentials.json` changes (e.g. the
account shape is regenerated by a later `init`), and neither the onboarding flag
nor the copy is captured by a script, so the manual steps are easy to get wrong.

Separately, the existing `06-trust-ca.sh` merges the proxy CA into Firefox's
`policies.json` with an embedded `python3` heredoc. That JSON-editing logic is
untested: the VM test guest has no Firefox, so the branch containing the python
never runs in the suite. We want to close that gap at the same time.

## Goals

- A single script sets `hasCompletedOnboarding` and puts the placeholder
  credential in place, replacing the manual `cp` in `usage.md`.
- The placeholder credential is a **symlink** back to the environment's
  `credentials.json`, so it tracks that file rather than snapshotting it.
- The script's JSON edit is covered by the VM test suite (`pnpm test:vm`).
- `06-trust-ca.sh`'s Firefox-policy JSON merge is covered by the same suite.

## Non-goals

- No change to how credentials are injected by the proxy or sanitized at `init`.
- No refactor of the python-in-bash into separately unit-testable modules — the
  VM harness exercises the real scripts, which is the honest place for this.

## Design

### New script: `templates/vm-shared/08-claude-config.sh`

Follows the `06`/`07` idiom: `set -euo pipefail`, `script_dir` resolved from
`${BASH_SOURCE[0]}`, `sudo` only where needed (none is needed here — everything
is under `$HOME`). The script:

1. `mkdir -p "$HOME/.claude"`.
2. Sets `hasCompletedOnboarding: true` in `~/.claude.json` via a `python3`
   heredoc that: reads the file if it exists (starting from `{}` on unparsable
   JSON, exactly as `06` does), sets the single key, and writes the file back
   pretty-printed with a trailing newline. All other keys are preserved.
3. Symlinks the placeholder credential into place:
   `ln -sfn "${script_dir}/credentials.json" "$HOME/.claude/.credentials.json"`.
   `-f` overwrites any prior file or symlink, making the step idempotent and
   replacing any earlier manual `cp`.
4. Prints an `08-claude-config: ...` summary line.

Notes:

- The file the CLI reads is `~/.claude.json` (with the leading dot), not
  `~/claude.json`.
- The symlink target lives on the **read-only** hgfs share
  (`/mnt/hgfs/vm-shared/credentials.json` in production;
  `/mnt/vm-shared/credentials.json` under the VM test harness). This is fine for
  reads. The placeholder's `expiresAt` is set to the year 2100, so the CLI never
  attempts a token refresh that would try to rewrite the (read-only) file. The
  script resolves the target from `script_dir`, so the link is correct in both
  the production and test mount locations.

### `usage.md`

In "Run the numbered scripts", replace step 8 (the manual `cp` block) with:

> 8. `08-claude-config.sh` — sets `hasCompletedOnboarding` in `~/.claude.json`
>    and symlinks the placeholder credential (`~/.claude/.credentials.json` →
>    the shared `credentials.json`) into place.

### `templates/vm-shared/verify-config.sh`

Update only the failure hint at the "Placeholder credential" check
(currently `"missing $cred -- copy vm-shared/credentials.json to it"`) to point
at `08-claude-config.sh` instead of the manual copy. No change to the check's
pass/fail semantics — a symlink to a valid placeholder file still passes the
existing `-f` and `grep` checks.

## Test coverage (`tests/vm/vm.test.ts`, S1 / NAT phase)

The S1 phase runs against the already-booted `g1` guest with the read-only share
mounted at `/mnt/vm-shared`; these checks need no network. All assertions read
JSON through `python3` so whitespace and key ordering are irrelevant.

### `08-claude-config.sh`

1. **Fresh file** — `rm -f ~/.claude.json`, run `08`, assert
   `hasCompletedOnboarding` reads back `true`.
2. **Merge + idempotent** — write `~/.claude.json` as `{"someExisting": 123}`,
   run `08` **twice**, assert both `hasCompletedOnboarding == true` and
   `someExisting == 123` survive. This is the case that proves the merge does not
   clobber existing content.
3. **Symlink** — assert `~/.claude/.credentials.json` is a symlink (`test -L`)
   whose target is `${share}/credentials.json`, and that reading through it
   yields the placeholder token (`grep sk-ant-oat-SANDBOX-PLACEHOLDER`).

### `06-trust-ca.sh` (Firefox policy merge)

The guest has no Firefox, so trigger `06`'s Firefox branch with a stub:

1. Drop a no-op executable named `firefox` on `PATH`
   (`printf '#!/bin/sh\n' | sudo tee /usr/local/bin/firefox; sudo chmod +x ...`)
   so `command -v firefox` succeeds.
2. Pre-seed `/etc/firefox/policies/policies.json` with an unrelated policy key
   **and** the stale Install entry
   `/usr/local/share/ca-certificates/configamatron-proxy-certificate-authority.crt`
   that `06` is meant to remove.
3. Run `bash /mnt/vm-shared/06-trust-ca.sh`.
4. Assert the merged `policies.json`: `Certificates.Install` contains
   `/etc/firefox/policies/configamatron-proxy-certificate-authority.pem`, does
   **not** contain the stale `/usr/local/...crt`, and the unrelated key is
   preserved.

These are added to the existing S1 block, so they extend an already-running
guest rather than booting a new one.

## Risks / open questions

- If a future change lets the placeholder credential expire, the CLI could try
  to rewrite the read-only symlink target and fail. Mitigated today by the
  year-2100 `expiresAt`; out of scope to guard further here.
