# 01: Ubuntu 26.04 installer kernel oops can hang the guest tier's golden image build

**Status:** resolved

**Category:** bug

**What happened:** On 2026-09-26 a full `pnpm test` (elevated, Windows 11 Pro 10.0.26200 host, first golden build on that machine) failed in the `guest` tier's global setup, before any guest test ran:

```
Error: goldenImage: build VM did not power off; see C:\code\susentorno\.image-cache\golden-build-serial.log
 ❯ waitForOff tests/guest/hyperv/goldenImage.ts:117:9
 ❯ ensureGoldenImage tests/guest/hyperv/goldenImage.ts:183:5
 ❯ Object.setup tests/guest/globalSetup.ts:28:3
```

The serial log showed the live installer's kernel oopsing in overlayfs while Subiquity was applying its autoinstall config, right after the Mirror step. The installer then hung, and `waitForOff` hit its 45-minute deadline. An immediate rerun of `pnpm test:guest` on the same commit and machine rebuilt the image cleanly and passed. So this is intermittent, not deterministic.

The failing commit was `f85d8a9` (codex real-account-id work). That change doesn't touch the golden image build, the autoinstall config, or the ISO.

- The autoinstall user-data sets no `drivers:` section, so Subiquity runs `ubuntu-drivers` by default. Check whether Subiquity still calls it just to list drivers.

### Triage update (2026-11-02): ready-for-human → ready-for-agent

The prerequisite (build-stall issue 03, the serial log writer) is resolved. Reading Subiquity's source answers the main open questions, and the judgment call that kept this ticket with a human is gone:

- **`drivers: { install: false }` would not help.** In Subiquity's `DriversController`, `install` already defaults to `False`. The *listing* run is separate from installing: `_list_drivers()` waits for `InstallerChannels.APT_CONFIGURED`, opens `Mirror.final_apt_configurer`'s `apt.overlay()`, and runs `ubuntu-drivers list` inside it. That matches the evidence: the oops came right after the Mirror step, in `ubuntu-drivers`, in `ovl_iterate_merged` under `getdents64`.
- **The switch is `source: { search_drivers: false }`.** `_list_drivers()` returns an empty driver list without running `ubuntu-drivers` when `Source.model.search_drivers` is false. `SourceController`'s autoinstall schema accepts `search_drivers: boolean`. When the key is missing, it is set to a default value that counts as true, so listing runs today. A Hyper-V test guest needs no third-party drivers.
- **Dropped:** waiting for an upstream kernel/ISO fix, and measuring the failure rate. The workaround is one key that removes the crash path, so neither would change what we do. The oops was never reproduced on demand (it is intermittent, and each build takes about 16 minutes).

## Agent Brief

**Category:** bug
**Summary:** Stop the guest tier's Ubuntu autoinstall from running `ubuntu-drivers`, the process that triggered the intermittent live-installer overlayfs oops.

**Current behavior:**
The autoinstall user-data that `buildUserData()` generates has no `source:` section. Subiquity therefore treats `search_drivers` as true. After the Mirror step it runs `ubuntu-drivers list` inside an apt overlay on the live session. On the 26.04 live kernel (`7.0.0-14-generic`), that run once oopsed in overlayfs (`ovl_iterate_merged`), and the installer hung until `waitForOff`'s deadline. The fail-fast kernel-failure check now turns such a hang into an immediate failure, but the build still fails.

**Desired behavior:**
The generated user-data sets `autoinstall.source.search_drivers: false`, so Subiquity never runs `ubuntu-drivers` during the golden build. A comment next to the key explains why (the overlayfs oops in the driver-listing run) and links this ticket. No other installer behavior changes. Because user-data is a golden-stamp input, existing golden images are rebuilt on the next guest-tier run without any manual step.

**Key interfaces:**
- `buildUserData(inputs: AutoinstallInputs): string`: its output gains a `source:` mapping under `autoinstall:` with `search_drivers: false`. Do not add a `source.id`; the default install source must stay the same.
- `GoldenStampInputs.userData`: already hashed by `computeGoldenStamp`, so the stamp changes automatically. Do not bump `BUILD_ALGORITHM_VERSION`.

**Acceptance criteria:**
- [ ] The parsed user-data from `buildUserData()` has `autoinstall.source.search_drivers === false`, asserted in the existing unit-tier autoinstall seed generator tests.
- [ ] The user-data still has no `drivers:` section, or one with `install: false`. Either way, nothing turns driver installation on.
- [ ] The full unit tier passes.
- [ ] One guest-tier run (`pnpm test:guest`, elevated, on a Hyper-V host) rebuilds the Ubuntu golden image and passes. The serial log (`test-results/golden-build/ubuntu/current/serial.log`) shows no `subiquity/Drivers` event that runs `ubuntu-drivers`. If this tier can't be run (not elevated, no Hyper-V), say so explicitly in the resolution rather than claiming it was verified.
- [ ] This ticket is marked resolved, with a short note of what changed and how it was verified.

**Out of scope:**
- Researching or pinning a newer Ubuntu point-release ISO or kernel.
- Measuring the oops failure rate with forced rebuilds.
- The Mirror-step stall (the 2026-11-01 stall with no kernel failure) and other golden-build-stall tickets.
- Changes to `findKernelFailure`, `waitForOff` deadlines, or serial-log handling.
- The Windows golden image.
