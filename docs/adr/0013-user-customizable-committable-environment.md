# The environment is user-customizable and source-controllable

A generated `.susentorno/` is meant to be committed, and users extend it without editing shipped scripts. `init` writes a bundled `.gitignore` that **inverts** the old "never commit `.susentorno`" guidance into an allowlist: ignore everything, then re-include only the user-authored surface (`pre-scripts/`, `post-scripts/`, `home-jq-transforms/`, `proxy/allowlist.txt`, the `.gitignore` itself). Everything the tool generates or that holds secrets (real credentials, private keys, `envoy.yaml`, build artifacts, per-environment placeholders) stays ignored by default. Two customization mechanisms feed the guest shares:

- **`home-jq-transforms/`** — a `manifest.yaml` + flat `.jq` files declaring edits to home-directory settings files. One tested TypeScript core (`src/homeJqTransforms.ts`) applies them both host-side (preview via `update-shares`) and in the guest (a tsup-bundled `apply-home-jq-transforms.mjs`); jq is the only transform language.
- **`pre-scripts/` / `post-scripts/`** — user setup scripts (`NN-name.sh`/`.ps1`) woven with the built-in scripts into the regenerated shares. Built-ins and customs are two solid blocks (no interleaving by number); the `nn-` sentinel keeps network isolation running last in the pre phase, so every custom pre-script runs before isolation with full network access.

## Considered Options

- **A denylist `.gitignore`** (commit everything except an enumerated secret set). Rejected: the list had to grow with every new generated file, and any unlisted new file got silently committed. Inverting to an allowlist means the committable surface is just what the user authors.
- **A shared jq helper library** across the guest scripts (an earlier idea) / **general templating**. Rejected in favor of one shared TS core and jq-only transforms.

## Consequences

- The whole `vm-shared-linux/` and `vm-shared-windows/` trees are fully regenerated by `init`/`update-shares` (stage-then-swap, whole-transaction: all validation passes before anything is written), so a deleted script/resource disappears rather than lingering.
- Because a `.gitignore` never untracks indexed files, upgrading a denylist-era committed environment needs `git rm -r --cached .susentorno && git add .susentorno`.
