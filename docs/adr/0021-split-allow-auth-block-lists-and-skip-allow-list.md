# Allow list, auth list, and block list replace the single allowlist file

The single `allowlist.txt` (passthrough + provider-authenticated + auth-candidate sections, per [[allowlist-format-and-parse-trust-boundary]]) is split into three files — `allow-list.txt` (flat passthrough-only `host:port` lines), `auth-list.txt` (the same pragma-sectioned credential-injection and auth-candidate entries, unchanged), and a new `block-list.txt` (bare hostnames, wildcards allowed, blocking a host on both `:80` and `:443`) — because a block list needs to unconditionally override entries in the other two files, and a `run-hosting --skip-allow-list` mode needs to turn off allow list enforcement without touching auth list's always-on credential injection. Neither need fit cleanly as another pragma section in one file. There is no migration path for existing `allowlist.txt` files; they're abandoned outright rather than auto-split, matching the project's tolerance for hand-maintained per-environment config at its current scale.

## Consequences

- Block list membership is resolved and pruned from the parsed allow/auth entries *before* the existing cross-section collision priority (auth candidate > provider-authenticated > passthrough, from [[allowlist-format-and-parse-trust-boundary]]) runs on what's left, so a host on the block list can never end up with a filter chain from either other file, even by accident.
- `--skip-allow-list` changes only the *default* (unmatched) branch of the proxy's 443/80 listeners from deny to open passthrough. It never touches auth list's chains, which stay TLS-terminated and credential-injected unconditionally — "explore the open web" and "manage credentials" stay orthogonal concerns.
- The access-log contract ([[envoy-access-log-contract]]) gains two tags, `ALLOW OPEN` and `BLOCK LIST`, and every line now prints `domain:port` instead of a bare domain, specifically so an `ALLOW OPEN` line can be pasted directly into `allow-list.txt`.
